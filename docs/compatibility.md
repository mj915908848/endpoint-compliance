# 管理端与客户端的版本兼容约定

版本号为 `主.次.序号`（如 0.2.23），`主.次` 来自 `VERSION` 文件，序号每次发布加一。同一 `主.次` 内的版本称为一个系列。

## 约定

1. **管理端兼容旧客户端。** 管理端支持不低于 `ReleaseVersion.MinimumAgent`（`src/Compliance.Core/ReleaseVersion.cs`，当前为 0.2.0）的全部客户端：照常登记、接收上报、判定和告警。客户端升级可以分批进行，不必和管理端同时升级。
2. **低于最低版本的客户端只降级，不拒绝。** 管理端仍接收它的心跳和上报，但终端列表、详情和导出把它标为「不受支持」。客户端从心跳回复读到最低版本后，在托盘提示员工联系管理员升级。比管理端旧、但不低于最低版本的客户端只标「待升级」。
3. **新客户端可以连旧管理端（同一系列内）。** 双方都忽略不认识的字段；客户端用到的新能力必须由管理端在回复里声明（如 `gzipUploads`、`lastSequence`、`minimumAgentVersion`），没有声明就按旧方式工作。
4. **协议只做向后兼容的修改。** 请求和回复只加可选字段，不改名、不删字段、不改含义。管理端需要区分客户端行为时，按心跳里的 `agentVersion` 判断，并在代码注释里写明从哪个版本起。
5. **数据格式版本。** 策略和快照的 `schemaVersion`（`Wire.SchemaVersion`，当前为 1）只在做不了兼容修改时才加一。加一的那个系列里，管理端同时接受新旧两种格式，客户端在管理端声明支持新格式后才发送新格式；直到最低客户端版本越过引入新格式的版本，才能去掉旧格式。格式不受支持的数据判为「无法判断」，不会判为通过。
6. **提高最低版本是一次显式变更。** 修改 `MinimumAgent` 的提交要同时更新本文件和发布说明，写明原因和受影响的客户端；只在旧客户端已无法正确判定（如数据格式、签名方式变化）或已超过一个系列时提高。

## 升级客户端

目前通过安装新版 MSI 升级（`msiexec /i compliance-client-<版本>-windows-x64.msi /qn`）：MSI 做主版本升级，保留登记信息和本地数据，拒绝降级。管理端「终端」页的版本标记用来找出需要升级的终端。

## 历史

| 版本 | 变化 |
| --- | --- |
| 0.2.8 | 心跳开始上报客户端版本；更早的客户端上报固定值 0.1.0，管理端记为空 |
| 0.2.9 | 管理端声明 `gzipUploads`，客户端随后压缩较大的上报 |
| 0.2.22 | 心跳带网卡信息 |
| 0.2.23 | 心跳回复带 `lastSequence`，本地队列丢失的客户端从管理端已有的序号继续 |
| 下一版本 | 心跳回复带 `serverVersion` 和 `minimumAgentVersion`；终端标出低于最低版本的客户端 |
